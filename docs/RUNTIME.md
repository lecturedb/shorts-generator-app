# 1차 실행·저장 운영 기준

상태: 1단계 확정안  
확정일: 2026-10-15  
대상: 개인 제작자용 macOS 로컬 환경

이 문서는 1차 구현이 전제로 삼는 실행, 저장, 비밀정보 및 장시간 작업의 범위를 정한다. 별도 서버 배포와 자동 작업 재개는 현재 범위가 아니다.

## 확인한 개발 환경

| 항목 | 확인 버전 |
| --- | --- |
| Node.js | 22.21.1 |
| npm | 10.9.4 |
| Next.js | 16.4.0 |
| React / React DOM | 19.3.0 |
| TypeScript | 5.9.3, strict mode |
| Tailwind CSS | 4.3.3 |
| Python | 3.12.7 |
| FFmpeg | 7.1 |

Node.js 주 버전은 `.node-version`과 `package.json`의 `engines`로 고정한다. 패키지 설치와 실행에는 npm 및 `package-lock.json`을 사용한다.

## 실행 위치와 프로세스 경계

- Next.js UI와 서버 기능은 사용자의 로컬 컴퓨터에서 실행한다.
- 브라우저는 입력, 실행 요청, 상태 조회와 미리보기만 담당한다.
- 프로젝트 파일 I/O, 외부 AI 호출, Python 및 FFmpeg 실행은 Next.js 서버 또는 서버가 시작한 로컬 작업 프로세스에서만 수행한다.
- Python과 FFmpeg에는 검증된 인수 배열을 전달한다. 사용자 입력을 셸 명령 문자열에 삽입하지 않는다.
- 렌더링 작업은 프로젝트 아래의 작업별 임시 디렉터리에서 격리한다. 구체적인 디렉터리 생성과 안전 저장은 4단계에서 구현한다.

기본 실행 명령은 다음과 같다.

```bash
npm install
npm run dev
```

검증 명령은 `npm run lint`와 `npm run build`다. 개발 서버는 Next.js 16.4의 기본 Turbopack을 사용한다. 빌드는 현재 로컬 자동화 환경에서 Tailwind 처리용 보조 프로세스의 포트 바인딩이 제한되는 문제를 피하기 위해 Next.js가 공식 지원하는 `next build --webpack`으로 실행한다.

## 프로젝트 파일 저장 위치

macOS 기본 위치는 다음과 같다.

```text
~/Library/Application Support/shorts-generator-app/projects
```

서버는 Node.js의 사용자 홈 디렉터리를 기준으로 위 경로를 해석한다. 다른 위치가 필요하면 `.env.local`의 `SHORTS_PROJECTS_DIR`에 절대 경로를 지정한다. 저장소 내부에는 실제 프로젝트 JSON이나 생성 미디어를 저장하지 않는다.

각 프로젝트는 고유 ID 디렉터리를 사용하고, 대표 데이터는 `project.json`, 미디어는 별도 하위 디렉터리에 둔다.

```text
projects/<project-id>/
  project.json
  script/
  images/
  videos/
  audio/
  output/
```

`project.json`은 스키마 검증을 통과한 뒤 같은 프로젝트 디렉터리의 고유 임시 파일에 기록하고 동기화한 다음 교체한다. 기록 또는 검증에 실패하면 기존 `project.json`과 완료 미디어를 유지하고 불완전한 임시 파일만 제거한다.

프로젝트 ID와 상대 경로는 서버 전용 저장 모듈에서 검증한다. 절대 경로, `..`, 역슬래시와 프로젝트 밖을 가리키는 경로는 거부하며 파일 목록에서는 심볼릭 링크를 따라가지 않는다. 누락 파일 조회는 프로젝트를 변경하지 않고 `missing` 상태와 복구 안내를 반환한다.

## 프로젝트 관리와 삭제

- 프로젝트가 하나도 없는 최초 실행에서는 샘플을 사용자 저장소에 자동 생성하지 않고 빈 상태를 표시한다.
- 프로젝트 생성·열기·검색·선택·이름 변경·수동 저장은 프로젝트별 `project.json`을 기준으로 동작한다.
- 프로젝트 삭제는 확인 대화상자에 `project.json`, 대본 데이터, 실행 이력과 미디어 파일 수를 안내한 뒤 사용자가 승인한 경우에만 실행한다.
- 확정 삭제는 휴지통이나 보존 기간 없이 해당 프로젝트 ID 디렉터리 전체를 영구 삭제한다. 다른 프로젝트 디렉터리는 변경하지 않는다.
- 읽기·검증·저장에 실패한 프로젝트는 자동 삭제하지 않으며 오류를 표시하고 기존 파일을 보존한다.

## 프로젝트 파일 조회와 미리보기

- 파일 트리는 실제 프로젝트 디렉터리의 파일과 `project.json`에 참조됐지만 누락된 자산을 함께 표시한다. 누락 파일은 자동 삭제하지 않고 원래 경로 복구 또는 해당 단계 재실행을 안내한다.
- 미리보기 파일은 프로젝트 ID와 정규화된 상대 경로를 서버에서 다시 검증한 뒤 제공한다. 절대 경로, 상위 경로 접근과 프로젝트 밖을 가리키는 심볼릭 링크는 거부한다.
- JSON·텍스트·일반 이미지·MP4/WebM·일반 오디오 형식만 인라인 미리보기를 허용한다. 미지원 형식은 파일 정보와 변환 안내만 표시한다.
- 영상과 오디오 제공 API는 브라우저 탐색 재생을 위한 바이트 범위 요청을 지원하고 응답을 캐시하지 않는다.
- 크기와 수정 시각은 실제 파일에서 확인하고, 생성 시각·해상도·길이는 저장된 자산 메타데이터가 있을 때만 표시한다.

## API 키 보관

- 로컬 키는 저장소 루트의 Git 제외 파일인 `.env.local`에만 둔다.
- 키는 `NEXT_PUBLIC_` 접두사를 사용하지 않으며 Server Component, Route Handler 또는 서버 전용 모듈에서만 읽는다.
- 키 값은 `project.json`, 샘플 fixture, 로그, 브라우저 응답과 내보내기 파일에 기록하지 않는다.
- `.env.example`에는 키 값이나 가짜 키를 넣지 않는다. 공급자별 변수 이름과 형식은 9단계에서 공식 문서 확인 후 추가한다.

## 장시간 작업 유지 범위

1차 지원 범위는 다음과 같다.

- 브라우저 탭을 닫아도 로컬 Next.js 서버와 작업 프로세스가 살아 있는 동안 작업은 계속된다.
- 실행 요청에는 고유 실행 ID를 부여하고 상태와 결과 참조를 프로젝트 데이터에 기록하여 다시 접속했을 때 조회할 수 있게 한다.
- 서버가 재시작되면 실행 중이던 작업을 자동 재개하지 않는다. 저장된 실행 상태를 `확인 필요`로 복원하고 사용자가 결과 확인 또는 재시도를 선택하게 한다.
- 완료된 파일과 앞 단계 결과는 재시작이나 재시도 때문에 삭제하지 않는다.
- 이 정책의 상태 저장과 중복 실행 방지는 8단계에서 구현한다. 외부 서비스의 원격 조회·취소 범위는 9단계에서 공식 지원 여부를 확인한 뒤 연결한다.

## UI용 샘플 자산

`fixtures/projects/sample-project.json`은 `project.json` v1 스키마를 따르는 표시·저장 검증용 fixture다. 앱은 Server Component에서 이 데이터를 런타임 검증한 뒤 UI에 전달한다. 저장 기능은 `lib/server/project-storage.ts`의 서버 전용 진입점을 사용한다.

샘플 미디어는 `public/samples/`에 있으며 외부 서비스 호출 없이 로컬 FFmpeg 소스로 생성했다.

- `scene-01.png`: 360×640 세로 이미지
- `clip-01.mp4`: 360×640 H.264 샘플 영상
- `narration.mp3`: MP3 샘플 내레이션 대역음
- `background.mp3`: MP3 샘플 배경음악 대역음
