# project.json 스키마 v4

`project.json`은 프로젝트의 대표 데이터다. 현재 타입과 런타임 검증 계약은 `lib/project-schema.ts`, 검증을 통과하는 예시는 `fixtures/projects/sample-project/project.json`에 있다.

## 최상위 도메인

| 필드 | 역할 |
| --- | --- |
| `schemaVersion` | 저장 형식 버전. 새 문서는 `4`, 기존 `1`~`3`은 읽을 때 v4로 변환 |
| `project` | 프로젝트 ID, 이름, 시각, 기본 출력 옵션과 전체 상태 |
| `workflow` | 고정 6단계의 포함 여부, 순서, 설정과 상태 |
| `script` | 공급자·모델·주제, 한 곳에만 저장하는 전체 대본과 목표 길이 |
| `scenes` | 장면별 시간·내레이션·시각 설명, 이미지 요청/상태, 영상화 선택과 편집 입력 |
| `assets` | 이미지·영상·오디오 파일의 프로젝트 내부 상대 경로와 메타데이터 |
| `runs` | 단계 또는 장면 실행의 상태, 시각, 오류 요약과 결과 자산 참조 |
| `voice` / `music` | 전체 대본 더빙과 배경음악 설정·상태·대표 자산 참조 |
| `editing` | 최종 편집 단계의 실행 상태·오류와 원본과 분리된 타임라인 배치 |
| `output` | 최종 렌더링 설정과 최종 출력 자산 참조 |

## 참조와 상태 규칙

- 프로젝트, 장면, 자산, 실행은 소문자 영숫자와 하이픈으로 된 고유 ID를 사용한다.
- 파일 경로와 대표 파일의 기준 데이터는 `assets`다. 장면·더빙·음악·실행·출력은 안정적인 자산 ID로 `assets`를 참조한다.
- `scene.assetIds`, 이미지/영상 선택 ID, `asset.sourceAssetIds`, `run.resultAssetIds`, `output.assetId`는 같은 문서에 존재하는 자산 ID만 참조한다.
- 장면 이미지 요청과 상태는 `scene.image`, 이미지 확인 뒤의 영상화 계획은 `scene.video`에 둔다. 영상화하지 않는 장면에는 시작·끝 이미지 참조를 저장하지 않는다.
- 장면 작업 상태는 `대기`, `요청 중`, `처리 중`, `완료`, `실패`, `확인 필요` 중 하나다.
- 장면에 속한 자산과 실행은 존재하는 `sceneId`만 참조한다.
- 자산 파일은 `/`, `..`, `.`, 빈 경로 조각과 역슬래시가 없는 프로젝트 내부 상대 경로만 사용한다.
- 상태는 `대기`, `실행 중`, `완료`, `실패`, `취소됨`, `확인 필요` 중 하나다.
- 대표 후보는 자산의 `selected`, 선행 결과 변경의 영향은 `stale.isStale`과 `stale.reason`으로 표현한다. 오래된 결과는 참조에서 제거하지 않는다.
- `editing.timeline`은 장면 대표 미디어 클립, 전체 더빙의 장면별 구간, 선택 배경음악 배치와 자막 트랙을 자산 ID와 초 단위 시간으로 저장한다. 공급자 음성 타임스탬프가 없으면 선택한 더빙의 실제 길이와 장면별 대사 분량으로 내레이션·자막 구간을 추정한다.
- 자막은 표시 여부, 지원 글꼴, 크기, 글자색, 외곽선색·두께, 위치와 장면별 텍스트·시작·종료 시간을 저장한다.
- 타임라인의 종료 시간은 시작 시간보다 커야 하며 장면 클립은 겹칠 수 없다. 영상 클립은 원본 영상 길이를 초과할 수 없고 모든 트랙은 역할에 맞는 기존 자산만 참조한다.
- 출력 설정은 `output.settings`에 저장하며 화면 비율은 `9:16` 또는 `1:1`, 해상도는 각 변 360~4320px, 프레임 레이트는 24/30/60fps, 품질은 `standard` 또는 `high`로 검증한다. 기본값은 `9:16`, `1080×1920`, 30fps, 표준 품질이다.

## 제외 데이터

- 이미지·영상·오디오 바이너리는 JSON에 넣지 않고 `assets.relativePath`로만 연결한다.
- API 키와 인증 정보는 타입에 포함하지 않는다. 단계 설정에서 키·토큰·비밀값으로 판단되는 이름은 런타임 검증에서 거부한다.
- 실제 파일 생성과 안전 저장은 `lib/server/project-storage.ts`에서 담당하며, 스키마 검증을 통과한 문서만 교체 저장한다.

## 이전 버전 호환 정책

- v1~v3 문서는 읽을 때 메모리에서 v4 구조로 변환하며 기존 `assets`, `runs`, `output`과 파일 경로를 보존한다.
- 변환된 문서를 다음에 저장하면 v4로 기록한다. 원본 파일은 검증과 임시 파일 기록이 성공한 뒤에만 교체된다.
- v1에 없던 공급자 설정과 시각 설명은 빈 값, 장면 시작 시각은 기존 장면 길이의 누적으로 복원한다.
